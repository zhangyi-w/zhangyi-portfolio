Product brief — the bet behind the build

Problem & insight
Gen Z is the most digitally-connected and the loneliest generation. Existing social apps optimize for online engagement, not real-world connection — the feed rewards watching, not meeting.
The bet: Make the shared plan the social object. You make friends by doing things together, not by posting. Offline activity is the unit of virality — "I went with 3 friends," not "I saw this online."
Why plans, not posts
Deliberately cut the public feed and follower-count vanity metrics. Optimized instead for low-friction plan creation → invite → RSVP → show up — the shortest path to a real-world meeting.
Judgment: A feed would have boosted session time but not the metric that matters — acquaintances converting into friends. We measure offline meetups created, not minutes scrolled.
Where we sit
Meetup connects strangers around interests. Partiful serves people you already know. SyncSo owns the gap between: turning acquaintances into friends through repeated shared activity.
Wedge: Campus communities — the acquaintance graph is dense but underused. High trust, high density, natural word-of-mouth loop.
Trust & safety by design
Abuse is designed out, not moderated after. Tiered authentication with role-based access means only verified members can publish plans. Onboarding is invitation-only with .edu email verification, and posting requires a real photo plus stated preferences and genuine intent to meet — raising the cost of bad actors before content exists.
Why it matters: a real-world social product lives or dies on trust. Identity assurance and a high-friction posting gate keep the network safe and high-signal as it scales.

AI integration — three production features

Embedding-powered discovery (22.8% engagement lift)
Spring Boot Discovery Service · OpenAI embeddings on user-profile features · real-time cosine-similarity ranking over multi-dimensional user context · powers the ForYou feed.
What's clever: Embeddings capture latent semantic context that hand-tuned signals miss. Lift measured as daily engagement increase over the prior heuristic baseline.
Bio generation
POST /users/{id}/bio:generate · GPT-4o · temperature 0 · 3× retry · sanitize → validate (10–20 words, English-only, no PII) · Caffeine cache 100K entries / 15-min TTL.
What's clever: AI failure ≠ user failure. Deterministic fallback ("Student at {school}, in {location}, into {tags}") activates if validation fails.
Friend recommendation
Multi-signal scoring — common-friend decay above 5, location boost, freshness bonus for new users (+8/+4/+2 by 30/90/180-day age band), random perturbation ±1, true random sampling via MongoDB $sample.
What's clever: Designed against industry playbooks — Facebook, LinkedIn, Twitter, Instagram patterns referenced before designing. Config-driven via application.properties — tune weights without redeploy.
School abbreviation search
Multi-priority match (exact abbrev > name contains > abbrev contains) · dedup via Set · merged with third-party API · MongoDB indexed.
What's clever: Respects user intent. "MIT" returns MIT, not 50 colleges with "MIT" in the name.
